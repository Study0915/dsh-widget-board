# 本地安全与范围规则

本文件适用于DS及后续在该工作副本工作的Agent。用户当前指令是最高的任务依据，工作区AGENTS列出每次开工流程。

## 1. 版本控制和投稿

允许：读源码、写计划、局部验证、按任务随时commit和push到Study0915/dsh-widget-board的任务分支，保存阶段进度。

当前关闭：向上游或其他仓库push、直接写master/main、推送tag、删除远端分支、非快进覆盖、创建/评论上游Issue、创建PR、合并远端PR、发布包或网站、改变权限。

origin下载和推送URL固定为自己的fork；upstream的fetch正常、push地址禁用。pre-push核对目标、任务分支和快进关系。gh/REST/浏览器写操作不经过Git hook，仍受上游投稿边界约束。

## 2. 真实环境

正式`.dsh`目录、凭据、共享技能、桌面profile和其他项目保持只读。只为核查版本读取特定package.json；不遍历或输出凭据文件、会话内容、个人卡片正文。

每个测试宿主设置独立DSH_HOME并核实其绝对路径位于本仓库.debug下；没有该变量时停止启动。进程pid和路径写入本次记录，退出只关闭自己启动的进程。

不杀死所有node/dsh进程，不修改全局npm/Git配置、不安装全局依赖、不全局改PATH。npm、Playwright、sharp等依赖及缓存放本工作区。

## 3. 文件修改

- 每次编辑前读取当前文件和git diff，保留用户变更。
- 每次只激活一个任务，写入范围由TASKS和局部policy共同限定。
- 新增公共行为按契约实现，不通过组件直接访问父DOM、网络、文件系统或shell。
- 密钥只经原凭据服务；日志、导出、样例、截图、URL均不含凭据值。
- 目录和资源路径由宿主构建；拒绝绝对路径、..、符号链接跨界和未知资源引用。
- 敏感基线包括原AGENTS、tokens、CSP、grants、HTTP访问限制、请求栅栏和统一检查脚本。检测变化时停止当前提交，说明必要性和具体替代检查，再问用户。
- 原源码接近750行时按原仓库停止线处理；本地工具不会替用户批准大文件继续扩张。

## 4. 清理和恢复

清理前核实绝对路径、归属与目录链接。只清理由本任务创建且已经不需要的.debug子目录。命令在同一种PowerShell环境内使用LiteralPath，不把枚举结果拼进cmd删除命令。

不执行reset --hard、git clean、force push、分支强删或递归删除工作区。临时worktree按原仓库专用脚本处理，防止Windows跟随node_modules链接删除主目录。

恢复用户撤回的内容必须先重新读取当前状态并使用编辑工具，不把旧内容机械加回。

## 5. 检查和报告

错误保持可见；遇到检查失败修实现或报告阻碍，保持原断言、限额和安全策略。删除测试、降低溢出标准、放宽CSP、自动批准权限或忽略校验均不属于修复。

普通commit/push只执行范围、安全和历史检查，允许保存尚未完成的版本。任务完成或PR准备前，真实宿主、浏览器、性能和视觉结果分别记录，每条证据含命令、退出码、代码指纹及路径。没有执行写“未执行”；通过guard不等于产品可用。

## 6. 工具能力边界

pre-commit阻挡错误分支、超范围文件和受保护文件变化；pre-push阻挡错误目标、主分支、tag、删除和非快进。complete命令另外检查完整验证和审阅证据。它们不拦截所有文件写入、外部API、Git --no-verify、修改本地配置或恶意程序。

因此保留DSH自身的文件权限、命令审批和可信工作区边界。不要给整个磁盘/用户主目录无条件写权限，也不要把这些文档描述为不可绕过的沙箱。对发布、凭据和删除动作使用宿主权限控制，并由用户明确决定。
