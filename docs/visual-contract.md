# 跨任务视觉契约

用户在 2026-10-25 确认提交 `676b878` 的 T04 外观为后续统一参照。本契约用于 DSH、Codex 和其他模型的全部 UI 修改；同一套规则适用于独立功能分支和集成分支。

## 修改顺序

1. 阅读当前任务与本契约，打开当前浅深色界面，列出本次涉及的卡片、弹窗、菜单及尺寸。
2. 先查 `packages/contracts/tokens.json`、`packages/client/src/visual.css` 和 `packages/runtime/src/suite/suite.css`。已有样式直接复用；通用调整写到共享层，组件文件仅处理自身内容布局。
3. 对每个改动给出对应的规则或明确的专用排版理由，再修改源码。
4. 运行完整 verify；其中的真实宿主冒烟会调用 `packages/testing/visual-contract.cjs`。检查值从 tokens 读取，新增卡片自动纳入字体检查。
5. 保存相同数据、视口、DPR 下的前后截图，实际打开浅深色、窄屏和矮盒子核对。记录文件与真实退出码后交接。

完成条件：每个修改的表面有规则依据、真实检查结果和已打开的截图。功能验证通过与用户视觉接受分别记录。

## 字体与排版

- 外壳使用宿主 `--dsw-font-family`；沙箱使用经现有主题通道解析的 `--w-font-family`。控制按钮、输入框和普通正文继承同一字体。源码、URL、标识和等宽数字可使用已有等宽族。
- 字号由 tokens 的 caption/body/title/heading/display 决定。普通正文使用 body，卡片标题使用 title，弹窗标题使用 heading，说明使用 caption。普通正文与说明采用 1.5 行高。
- 卡片变宽、变高时增加可见内容和留白，普通正文保持 body 档。时钟、倒计时主读数、统计值和图表坐标属于专用排版；它们保留自身响应式比例，并在组件样例中覆盖。
- 标题、说明、正文各有独立区域。长标题在当前区域换行或截断，长列表在正文区域滚动；操作入口始终可达。

## 留白与控件

- 常规数据卡和待办使用 xl 内边距、md 内容区间距。宽度或高度不超过 320 CSS px 时使用 md 内边距、sm 间距，标题缩为 body；正文维持 body。
- 编辑器和表单继续复用 T04 的 editor/composer 外壳。管理弹窗使用相同字体层级、题头与页脚间距；菜单说明使用 caption。
- 卡片圆角沿用 card 令牌；按钮、标签和输入框沿用现有编辑器对应控件。交互反馈、禁用、错误和焦点状态同时实现。
- 配色使用宿主语义别名与运行时颜色令牌，浅深色切换沿用原主题服务。装饰色仅用于图表分类、状态和已有专用动效。

## 分支与证据

当前 T00、T01、T02、T03/T04 保持各自功能分支；共享视觉修正以同一提交或对应的 cherry-pick 传播，分支特有界面另行记录。视觉统一不提前导入其他任务的功能。

至少核对原生及当前兼容主题的浅深色、1920×1080、1440×900、1024×768 和单列；卡片通过原尺寸矩阵检查，菜单/弹窗核对键盘焦点及关闭路径。只比较稳定的字体、层级、间距、溢出和操作可达性；数字、时钟和动效画面不做逐像素断言。

截图和日志存于 `.debug/evidence/TVISUAL/`，审阅记录按分支保存。新模型继续任务时先读取本契约和最新交接，使用当前源码与当前指纹，保留既有结果。
